Phase 5 parity evidence: the dbt build replaces the hand-written SQL build in place
============================================================================================
Date: 2026-10-14 (UTC). Snowflake MARKETING_CRM, role CRM_TRANSFORMER (no secondary roles),
warehouse MARKETING_WH (X-Small). dbt Core 1.12.5 + dbt-snowflake 1.12.2, run from the repository root,
one target (`prod`): every dbt run replaces the live STAGING and MART objects.

Procedure (every step is a make target; steps 1 and 2 build, all others are read-only)
  1. make parity-snapshot PARITY=before  sql/parity/parity_snapshot.sql on the SQL-built objects
                              (the `make models` state of Phases 3-4), taken before the first dbt run
                              -> build/parity_before.txt
  2. make dbt-build           parse (0 deprecations), dbt build (PASS=273 WARN=0 ERROR=0 SKIP=0 NO-OP=2 TOTAL=275),
                              source freshness (8 of 8 PASS), docs generate -> docs/evidence/05_dbt_build.txt
  3. make parity-snapshot PARITY=after && make parity-diff
                              the same snapshot on the dbt-built objects, compared field by field (A)
  4. make parity-check        scripts/parity_minus.py: the 18 hand-written CREATE bodies of sql/02*.sql
                              rebuilt from RAW as CTEs in one query per object and compared with the
                              deployed dbt objects (A.3). Creates nothing and needs no SQL build, so it
                              can be repeated at any time without overwriting the dbt build.
  5. make sql-checks          the 7 hand-written SQL check files, read-only, on the dbt build (C)
  6. make seeds-check         the independent seeds regenerated from the CSV files (E)
  The 'before' snapshot only exists while the SQL build is deployed (steps 1-3); steps 4-6 do not
  depend on it. `make models` (the legacy SQL build) would replace the dbt-built objects.
